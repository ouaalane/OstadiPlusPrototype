# OstadiPlus — interactive product prototype

One demo dataset, two finished-looking apps:

| App | Stack | What it is |
| --- | --- | --- |
| `apps/teacher-dashboard` | React + TypeScript + Vite + Tailwind | لوحة الأستاذ — courses, chapters/lessons, uploads, students & access, announcements |
| `apps/student-app` | React Native (Expo SDK 54) + TypeScript | تطبيق التلاميذ — Android, offline: splash, sign-in, home, my courses, course detail, video player, document reader, announcements, profile |
| `apps/api` | Node ≥ 23.6, zero dependencies (`node:http`, `node:sqlite`) | Watermark API — issues + traces the per-playback video codes (optional at runtime) |

Everything is **Arabic / RTL**, the brand name stays **OstadiPlus** in Latin script, and both apps read the same
seed from `packages/shared` (`seed.ts` + `media-manifest.json`). No remote backend, no payments, no real
accounts — changes are stored locally on each device. The only server-side piece is the local **watermark API**
(`apps/api`): it hands the player a traceability code on every playback start and keeps the leak-tracing
ledger; the apps still run fully offline without it.

---

## The demo story (≈60 seconds)

1. **Teacher** — `npm run dashboard` → open **الدورات** → «تحضير الامتحان الوطني» (مسودة) → add a chapter + a
   lesson from the media library → **نشر الدورة**.
2. **Teacher** — **الطلاب** → expand a student (e.g. كنزيا باحاج) → **تفعيل** on the exam course. (Or add a new
   student with «تفعيل الوصول فوراً».)
3. **Teacher** — **الإعدادات** → «نسخ رمز المزامنة».
4. **Student app** — launch → pick that student on the sign-in screen → the newly published course is there →
   open a video lesson → watch, close, reopen: it resumes where you left → mark it complete.
5. Back on the dashboard the same actions are already reflected in the shared dataset (after step 3 sync), and
   the student's progress is saved on the phone.

## Quick start

```powershell
# 1. install the workspace (shared + dashboard)
npm install

# 2. install the phone app (it has its own lockfile, outside the workspace)
npm --prefix apps/student-app install

# 3. regenerate + distribute the demo media (videos, PDFs, page images, manifest)
npm run media

# 4. teacher dashboard → http://localhost:5173
npm run dashboard

# 5. student app (Metro bundler) — in a second terminal
npm run app          # then press "a" for Android, or scan the QR with Expo Go

# 6. (optional) watermark API — the player asks it for a traceability code per playback
npm run api          # http://localhost:8787 (the emulator reaches it as 10.0.2.2:8787)
```

### Run the Android app on an emulator

```powershell
# start the emulator (AVD that already exists on this machine)
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -avd Pixel_9a

# run the app in dev mode (fast refresh, Metro serves the JS bundle)
npm run app
```

### Build & install a standalone APK

```powershell
$env:JAVA_HOME    = 'C:\Program Files\Android\Android Studio\jbr'   # JDK 17
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
Set-Location apps\student-app\android
.\gradlew.bat :app:assembleDebug

# install on whatever adb currently sees
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
```

The native `android/` folder is generated by Expo (`npx expo prebuild --platform android --no-install`) —
delete it and re-run prebuild whenever `app.json` or native dependencies change.

> **Machine-specific tweak:** `android/gradle/wrapper/gradle-wrapper.properties` points at the `gradle-8.14.3-all`
> distribution, which is already cached in `%USERPROFILE%\.gradle\wrapper\dists` (the `-bin` download times out
> here). After re-running `expo prebuild`, re-apply that one-line change if Gradle tries to download again.

### Video watermark & screen capture

Every video playback start calls the watermark API (`POST /api/playback/start`), which validates the student's
enrollment and returns a fresh 12-character Base32 code (no `0/O/1/I/L`). The player renders **only that code** —
two dim white copies that fade-move between random positions every 8–15 s, never over the bottom controls or the
dead centre, and unmount entirely while paused. Trace a leaked code with:

```powershell
npm run api:trace -- K7M2QX9TPA4W
# or over HTTP:
# curl http://localhost:8787/api/admin/watermarks/K7M2QX9TPA4W -H "x-admin-token: dev-admin-token"
```

While the player is open the app blocks screen capture (FLAG_SECURE on Android — `adb screencap` returns a black
frame; `expo-screen-capture` also reports capture attempts). Without the API the app still runs: it renders an
unregistered local code (flagged in `apps/student-app/src/lib/watermark-api.ts`), and the ledger lives in
`apps/api/data/watermarks.db` (git-ignored).

## Demo data, sync & reset

* **Seed** — `packages/shared/src/seed.ts`: 4 courses (1 published draft included), 14 students, enrollments,
  3 announcements, and saved progress for إمان السيد.
* **Sync payload** — teacher dashboard **الإعدادات → نسخ رمز المزامنة** produces an `OSTADI1:…` string
  (deflate+base64 in the browser, plain base64 on the phone). Paste it in the app (**ملفي → مزامنة مع لوحة
  الأستاذ**, or on the sign-in screen) to pull the teacher's latest dataset onto a second device.
* **Reset the dashboard** — **الإعدادات → إعادة ضبط البيانات** (restores the shipped seed in localStorage).
* **Reset the phone app** — **ملفي → إعادة تعيين بيانات العرض**, or clear the app's storage
  (`adb shell pm clear ma.atlas.ostadiplus.student`).

## How the demo media is produced

`npm run media` (`scripts/generate-media.mjs`) is fully offline and deterministic:

1. every lesson slide is rendered to 1280×720 PNG with headless Chromium (Arabic IBM Plex Sans Arabic),
2. ffmpeg stitches the slides into an MP4 with a subtle RTL progress bar (CRF 30, ≈1 MB per lesson),
3. the same engine prints 5 PDF worksheets (A4) **and** rasterises each page to PNG for the phone's reader,
4. real durations/sizes are probed and written to `packages/shared/src/media-manifest.json`,
5. `scripts/sync-media.mjs` copies everything to
   * `apps/teacher-dashboard/public/media` (served as `/media/…`), and
   * `apps/student-app/src/assets` **plus** `src/assets/registry.ts` (the generated `require()` map Metro needs).

Re-running with `OSTADI_MEDIA_RESUME=1` keeps existing videos and only redoes what is missing.

## What is deliberately out of scope

* **No backend / cloud / accounts** — auth is «pick your name», persistence is `localStorage` (web) and
  `AsyncStorage` (Android); the two apps exchange data through the copy-paste sync payload.
* **No payments** — enrollments are granted by the teacher (PRD ENR-03: cash is recorded at the centre and
  never gates access in the prototype).
* **No quizzes engine, certificates, analytics, multi-teacher roles, licences or anti-sharing** — the PRD
  mentions them; the prototype stops at the interaction that proves the product.
* **The phone's document reader shows rasterised PDF pages** (bundled PNGs) instead of a native PDF engine —
  deterministic, offline, and identical on every device.
* **RTL is laid out explicitly** (`flex-direction: row-reverse`, right-aligned text) rather than depending on
  an `I18nManager` restart, so the first launch is already correct.
* Uploaded files in the dashboard live in IndexedDB per browser and reset with «إعادة ضبط البيانات».
