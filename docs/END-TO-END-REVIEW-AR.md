# مراجعة أستاذي Plus: التطبيق والداشبورد

التاريخ: 22 أكتوبر 2026. النطاق: النسخة التجريبية الحالية، مع خادم المزامنة المحلي الحقيقي، متصفح Chromium وواجهات التطبيق الفعلية. الاختبارات تستعمل بيانات ومجلدات مؤقتة معزولة؛ لا تستبدل بيانات المركز المحفوظة.

## الأخطاء المؤكدة والإصلاحات

| المشكل الذي أُعيد إنتاجه | الإصلاح | دليل التحقق |
|---|---|---|
| التسجيل يقبل إيميلاً غير صالح ويتيح تكرار إيميل حساب موجود؛ سياسة كلمة السر تختلف عن تعديل البروفايل | نفس التحقق عند الانتقال والتأكيد وفي store: صيغة الإيميل، عدم تكراره دون اعتبار حالة الأحرف، الهاتف الاختياري، و8 أحرف لكلمة السر كما في البروفايل | إدخال بيانات غير صالحة من واجهة التسجيل ثم إنشاء حساب صحيح ومستقل |
| سؤال بجواب واحد يسمح باختيار جوابين معاً، فتكون النتيجة خاطئة | الجواب الجديد يستبدل القديم في الاختيار الواحد؛ الاختيار المتعدد يحتفظ بالتبديل؛ حالة الاختيار متاحة أيضاً لقارئ الشاشة على الويب | اختيار جواب خاطئ ثم الصحيح؛ التأكد من اختيار واحد فقط، ثم اختيار جوابين في سؤال متعدد والحصول على 2/2 |
| إعادة التحميل مباشرة بعد تبديل الحساب قد تعيد المستخدم السابق بسبب تأخير حفظ الجلسة 350ms | حفظ تغييرات الحساب والبروفايل والمزامنة فوراً، وتأخير تحديث تقدم المشاهدة فقط | تسجيل الخروج والدخول بزائر آخر ثم reload فوري والتأكد من هوية الزائر الثاني |
| المفضلة والأرشيف مشتركان بين حسابين على نفس الجهاز | حفظ الإعدادات حسب معرف التلميذ؛ نقل الإعدادات القديمة لآخر حساب محفوظ فقط، مع إبقاء المفتاح القديم دون حذفه | تبديل الزائرين وإعادة التحميل ثم الرجوع لصاحب المفضلة والأرشيف |
| مولد رمز الطالب القديم له 32 مخرجاً فقط؛ ثلاثة تلاميذ تجريبيين يشتركون في `UST-N58FA` | مولد مشترك في التطبيق والداشبورد يستعمل مساحة الرموز كاملة ويتحقق من التصادم؛ إصلاح التكرار القديم عند التحميل والمزامنة وفي الخادم | 2,000 رمز جديد دون تكرار، وإصلاح النسخة القديمة، وتصادم التسجيل من جهاز آخر، وإعادة تشغيل الخادم |
| PDF يبقى قابلاً للعرض بمعرف درس محفوظ بعد انتهاء اشتراك قديم؛ النص والكويز لا يتحققان من الوصول عند فتح المسار | نفس التحقق من الاشتراك والنشر لكل أنواع الدروس؛ عرض رسالة مفهومة بدل الشاشة الفارغة عند غياب الدرس أو الصلاحية؛ عدم إصدار watermark جديد لـPDF محجوب؛ منع تشغيل فيديو مسودة | مسارات مباشرة لكل من الفيديو وPDF والنص والكويز: اشتراك منتهٍ/غائب، دورة غير مشتراة، مقرر أو درس مسودة |

تصحيح الرموز القديمة تم بموافقة صاحب المشروع: يحتفظ أول صاحب للرمز به، وتتغير النسخ المكررة فقط. مثلاً يحتفظ ياسين بـ`UST-N58FA`، ويصبح رمز صفاء `UST-SMHFC` ورمز هبة `UST-YLNNG` في بيانات العرض الأصلية. معرفات الحسابات، الاشتراكات والتقدم لا تتغير. **رسم QR بقي تجريبياً وغير قابل للمسح بالكاميرا، حسب طلب صاحب المشروع.** رمز `UST-…` معرف وليس كلمة سر أو تصريح وصول.

الإعدادات القديمة للمفضلة لم تكن تتضمن صاحبها؛ لذلك تنسب لآخر حساب محفوظ إن وُجد. لا ننقلها لجميع المستخدمين، ولا نخمن صاحبها إذا لم يكن هناك حساب محفوظ.

## الفحوصات

- 69 اختباراً لتطبيق التلميذ: كلمات السر المحلية، البحث عن الحساب، البروفايل والصورة، الإشعارات وExpo Go، تدوير الفيديو، إخفاء أدوات التحكم، حماية المحتوى، والتحقق الجديد للتسجيل والإعدادات الشخصية.
- 4 اختبارات هندسة زوم PDF، منها حدود التحريك والمحافظة على نقطة اللمس وإرجاع 100%.
- 13 فحصاً لقواعد إنشاء الكويز واستيراد JSON والتحقق قبل النشر.
- 17 رحلة فعلية في واجهة الداشبورد: إنشاء المقرر والفصل، إلغاء الرفع وإعادة المحاولة، رفع الفيديو وPDF، الصورة المصغرة والوصف، الكويز، المسودات والنشر، حماية التعديلات غير المحفوظة، الاشتراكات، الأجوبة، المكتبة والبحث.
- 21 فحص تكامل API: الملفات وطلبات Range، النشر، التسجيل، التقدم، الأسئلة والأجوبة، النتائج والحفظ بعد إعادة التشغيل.
- 11 فحص اشتراك: شهر/شهران/ثلاثة، تواريخ المغرب، نهاية الشهر، نهاية الدورة، الاشتراكات المستقبلية، وحدود الدورة الأولى والثانية.
- 24 فحصاً للواترمارك وإصداره وتتبع الطالب والمقرر والدرس ورفض الطلبات غير المسموحة.
- تشغيل فعلي لـ32 فيديو في المتصفح: جميع الفيديوهات المضمنة وفيديو مرفوع، بأبعاد عمودية وأفقية؛ فحص تتبع الأكواد، 33 ثانية متواصلة بدون اختفاء الواترمارك، الإيقاف والاستئناف، API بطيء، وإعادة المحاولة والعمل التجريبي دون اتصال.
- 16 رحلة مشتركة ناجحة عبر واجهتي التطبيق والداشبورد: إنشاء حساب، تعديل صورة وبيانات وباسورد، تسجيل الخروج والدخول، المزامنة، نشر المحتوى والتفعيل، السؤال والجواب، PDF المرفوع وزومه، الكويز العادي والمؤقت ونتائجه، الزائران، عزل المفضلة، البحث، ورفض الوصول. النتائج المحفوظة: [سجل الرحلات الفعلي](verification/app-journeys-2026-10-22.json).
- TypeScript للتطبيق والداشبورد، وبناء إنتاجي للداشبورد، وJavaScript bundles لكل من Android وiOS. Lint: صفر أخطاء و44 تحذيراً موجودة سابقاً، خارج نطاق الإصلاحات.

- 13 شاشة للتلميذ باللغتين العربية والفرنسية في عروض 320 و390 و768 بكسل، و10 صفحات للداشبورد في عروض 320 و390 و1440 بكسل: لم يظهر تجاوز أفقي للصفحة أو خطأ JavaScript غير معالج. راجعت صور الواجهات أيضاً؛ هذه المراجعة ليست مقارنة pixel-perfect ولا اختباراً لكل إعداد تكبير نص. التطبيق حالياً يستعمل الثيم الفاتح.

## إعادة التشغيل

من جذر المستودع، بعد تثبيت اعتماديات الجذر و`apps/student-app`:

```sh
node --test apps/student-app/scripts/test-*.cjs
node --test check-pdf-zoom.mjs
npm run dashboard:test
npm run dashboard:build
npm run access:test
node scripts/check-demo-sync.mjs
node check-watermark.mjs
npm run test:journeys
node scripts/check-video-watermarks.mjs
```

لحفظ الصور وملف نتائج الرحلات في مجلد تختاره:

```sh
OUSTADI_SCREENSHOT_DIR=/tmp/oustadi-journeys npm run test:journeys
```

على PowerShell:

```powershell
$env:OUSTADI_SCREENSHOT_DIR = "$env:TEMP\oustadi-journeys"
npm run test:journeys
```

تحتاج اختبارات المتصفح Chromium: `npx playwright install chromium`، أو تحديد `PLAYWRIGHT_CHROMIUM_PATH` لمتصفح مثبت. الاختبارات تشغل خوادمها ومنافذها المؤقتة، وتغلقها في النهاية. معاينة تطبيق التلميذ تستعمل الواجهة الحقيقية مع بديل واضح لـfilesystem الأصلي؛ عمليات التنزيل الأصلية تفشل عمداً بدل ادعاء نجاحها في المتصفح.

## حدود التحقق

هذه ليست شهادة بأن كل احتمال أو كل جهاز اجتاز الاختبار. لا يتوفر هنا Android SDK/adb أو Xcode أو هاتف iOS/Android متصل. لذلك لم يُختبر فعلياً على جهاز:

- منع screenshots أو تسجيل الشاشة والصوت، وسلوك app switcher؛ Expo Go يبقى معاينة دون هذه الحماية.
- الدوران بحساس الهاتف وأزرار النظام، والتنزيل الحقيقي وإدارته بعد إغلاق التطبيق، وصلاحيات اختيار الصور الأصلية.
- إشعارات النظام/FCM في الخلفية، مشاركة البطاقة والحافظة، واسترجاع الجلسة بعد قتل عملية التطبيق على النظام.

تغيير أبعاد متصفح لا يعادل تدوير هاتف. بناء JS لا يعادل بناء APK/IPA أو تجربة أصلية. مصادقة الخادم/DRM ونقل الأكواد بالبريد ليست مضافة: تبقى المصادقة محلية ورمز التأكيد من ستة أرقام تجريبياً كما في النسخة الحالية. المزامنة يدوية، وتحديث حالة انتهاء الوصول في الواجهة يستعمل ساعة التطبيق الحالية ذات دورة 30 ثانية. هذه سلوكيات حالية موثقة وليست ميزات إنتاجية تم اعتمادها بهذه المراجعة.
